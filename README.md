# Transfer Learning on the Kaggle Dogs vs. Cats Dataset

This repository presents a compact computer vision case study: fine-tuning a pretrained CNN on Kaggle's classic **Dogs vs. Cats** dataset.

The accompanying Quarto website documents the reasoning behind the approach and is available at:

**[https://ianlopezdiaz.github.io/kaggle-cats-vs-dogs](https://ianlopezdiaz.github.io/kaggle-cats-vs-dogs)**

---

## Project Overview

Dogs vs. Cats is a binary classification task over real photographs (varied lighting, pose, background, and occlusion) rather than a clean, canonical dataset like MNIST. The objective here is a real, current computer vision workflow: fine-tune a pretrained backbone (transfer learning) rather than train from scratch, evaluate beyond accuracy, and visualize what the model is actually attending to with Grad-CAM.

The complete pipeline includes:

* Stratified train/validation split and a standard photographic augmentation pipeline
* A pretrained ResNet18 backbone, fine-tuned with a replaced binary classification head
* Evaluation beyond accuracy: confusion matrix, per-class precision/recall/F1
* Grad-CAM visualization of model attention on correct and incorrect predictions
* Error analysis on the most confidently wrong predictions

---

## Dataset

The project uses the **Dogs vs. Cats** dataset from Kaggle.

* Competition: [https://www.kaggle.com/competitions/dogs-vs-cats](https://www.kaggle.com/competitions/dogs-vs-cats)

25,000 labeled training photographs (cat vs. dog).

## Running the Project

### Install the dependencies

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

### Get the data

Download and unzip the [competition data](https://www.kaggle.com/competitions/dogs-vs-cats/data) into `data/raw/`, so that `data/raw/train/` contains the labeled `cat.N.jpg` / `dog.N.jpg` images.

### Run the notebooks

```bash
jupyter lab notebooks/
```

Run them in order: `01_eda.ipynb`, `02_training.ipynb`, `03_evaluation_and_gradcam.ipynb`.

### Run the tests

```bash
pytest
```

## Building the Documentation

This repository uses **Quarto** to generate the project website.

Preview the website locally:

```bash
quarto preview
```

Render the complete site locally (output goes to `_site/`, which is gitignored and not committed):

```bash
quarto render
```

### Publishing

Publishing is automated. The workflow in `.github/workflows/publish.yml` renders the site and pushes it to the `gh-pages` branch on every push to `main`.

The one manual step is the very first publish, which creates the `gh-pages` branch:

```bash
quarto publish gh-pages
```

After that, pushing to `main` is enough.

Note that CI renders the notebooks **as committed and does not execute them**, because the dataset and the trained checkpoint are both gitignored and training needs a GPU. Run the notebooks locally and commit them with their outputs; those stored outputs are what the published site displays.
